# Flutter 앱 초기화 계획

## 입력 자료에서 확인한 제품 범위

- 핵심 루프: 지역 탐색 → 사진 상세 → 추천·댓글·저장 → 지역·테마 랭킹
- 핵심 기여 흐름: 사진 선택 → GPS 기반 관광지 매칭 → 게시
- 주요 탐색: 17개 시도 커뮤니티, 관광지명 검색, 지도 주변 탐색, 관광지 상세
- 확장 범위: 다국어 UI·UGC 번역, K-컬처 촬영지·작품 정보, 알림과 개인화
- 화면 구조: 홈·랭킹·업로드·지도·마이 5개 진입점. 업로드는 모달 화면으로 처리

## 템플릿 결정

### 선택: 공식 `flutter create --empty`

공식 Flutter 템플릿을 최소 기반으로 사용하고 프로젝트에 필요한 구조만 추가한다.

- Flutter SDK와 함께 버전이 관리되어 팀원이 재현하기 쉽다.
- 특정 상태 관리나 서버 구성에 앱이 먼저 종속되지 않는다.
- Android/iOS 네이티브 기본 설정이 표준 형태로 생성된다.
- 기능이 확정될 때 필요한 패키지만 추가할 수 있다.

### 이번에 선택하지 않은 대안

- Very Good CLI: 테스트, flavor, Bloc 기반 구조를 빠르게 제공하지만 MVP 단계에서 사용하지 않을 구성까지 먼저 고정한다. CI와 dev/staging/prod 환경이 확정되는 시점에 설정 방식을 참고한다.
- 대규모 Flutter starter kit: 인증·네트워크·로컬 저장소가 포함된 템플릿은 백엔드 계약이 정해지기 전에 교체 비용을 만든다.

## 초기 아키텍처

```text
lib/src/
├── app/                 # 라우터, 테마, 앱 전역 조립
├── core/                # 기능에 종속되지 않는 공통 UI와 기반 코드
└── features/            # 사용자 기능 기준 모듈
    ├── auth/
    ├── home/
    ├── rankings/
    ├── upload/
    ├── map/
    └── profile/
```

기능 내부는 필요한 만큼 `presentation`, `domain`, `data`로 확장한다. 빈 레이어를 미리 만들지 않는다. 외부 API는 repository 인터페이스 뒤에 두고 TourAPI, 인증, 업로드 구현을 교체 가능하게 만든다.

## 기반 기술

- `go_router`: 딥링크와 탭별 탐색 상태 보존
- `flutter_riverpod`: 상태 관리와 repository/service 의존성 주입
- Material 3: 공통 테마와 접근성 기본값

지도, 위치, 카메라/갤러리, HTTP 클라이언트, 번역 패키지는 공급자와 API 계약을 정한 뒤 기능 단위로 도입한다. 그전에는 네이티브 권한을 추가하지 않는다.

## 구현 순서

1. 앱 셸, 테마, 라우팅, 온보딩 흐름
2. TourAPI 기준 관광지 모델·repository와 검색/상세
3. 인증과 17개 지역 피드
4. 사진 선택·업로드와 GPS 관광지 매칭
5. 추천·댓글·저장 및 랭킹
6. 지도 SDK 연동
7. 다국어 UI, UGC 번역, K-컬처 메타데이터
8. flavor, CI, 통합·골든 테스트 강화

## 초기 완료 기준

- Android/iOS 프로젝트가 생성되어 있다.
- 온보딩부터 홈까지 이동할 수 있다.
- 5개 주요 진입점과 상세 화면 라우트가 연결되어 있다.
- 포맷, 정적 분석, 위젯 테스트가 통과한다.
