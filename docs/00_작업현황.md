## 3-1. 겪은 문제와 해결 (2026-08-21)

| 문제 | 원인 | 해결 |
|---|---|---|
| `bootRun` 이 4초 만에 죽음 | `Schema-validation: wrong column type ... [replaced_by] found [char] but expecting [varchar(64)]` | 스키마 타입 38곳을 엔티티 기본 매핑에 맞춤 |
| 같은 유형 오류가 38곳 | 스키마는 MySQL 최적화 타입(`ENUM`/`CHAR`/`TINYINT`), 엔티티는 기본 JPA 매핑(`VARCHAR`/`INT`) 으로 **각각 따로 작성** | `ENUM`(32) → `VARCHAR(30)` + `/* 허용값 */` 주석, `CHAR(64)`(4) → `VARCHAR(64)`, `TINYINT`(2) → `INT`. 엔티티 enum 필드에 `@Column(length = 30)` 명시 |
| 재발 방지 | — | `CLAUDE.md` 코드 규약에 **DB 타입 규약**으로 못박음. 남은 24개 테이블에 엔티티를 쓸 때 이 규약을 따르면 같은 문제가 안 생긴다 |
| 적재는 됐는데 `createdCount: 0` | JDBC URL 의 `rewriteBatchedStatements=true` 가 배치를 다중행 INSERT 로 재작성 → 행별 결과가 실제 영향 행수가 아니라 `Statement.SUCCESS_NO_INFO(-2)` 로 반환. `if (r==1) created++ else if (r>=2) updated++` 가 전부 실패 | 배치 반환값 의존을 없앰. 넣기 전에 `SELECT COUNT(*) ... WHERE content_id IN (...)` 로 기존 건수를 세서 정확히 집계. `sync_logs.message` 에 `fetched=N skipped=N` 기록 추가 |

**교훈**: `595건 적재 + 0건 집계` 처럼 **"성공했다는 응답"이 거짓일 수 있다.** API 응답만 믿지 말고 DB 를 직접 세어봐야 한다. 이번에 `SELECT COUNT(*)` 한 번으로 잡았다.

**부수 이득**: MySQL `ENUM` 을 버려서 값 추가 때마다 `ALTER TABLE` 이 필요한 문제도 사라졌습니다. 유효성은 Java enum 이 보장합니다.

| 2 | 게시글 업로드는 **로그인 필수** | 익명 업로드 폐기 | [확정] |
| 3 | 업로드는 **별도 화면** (팝업/시트 아님) | 프론트 요청 | [확정] |
| 4 | 랜딩 = **지도 + 히트맵** | 공모전 차별점 | [확정] |
| 5 | 하단 탭 5개: 홈 / 커뮤니티 / 업로드 / 이벤트 / 마이 | | [확정] |
| 6 | "실시간" = **60초 폴링**. 웹소켓·SSE 안 씀 | 시연 규모에 과함, 서버가 갱신 주기(`nextRefreshAt`) 통제 | [확정] |
| 7 | 사진·게시글 테이블 통합 → `posts` + `post_media` | 이전 설계의 photos/posts 중복 제거 | [확정] |

| 9 | 장소 선택은 **게시글 작성 화면 안에서** | 이 단계를 빼면 Tier·랭킹·방문기록이 전부 죽음 | [확정] |

| 12 | TourAPI는 **배치로 우리 DB에 적재**, 사용자 요청 때 직접 호출 안 함 | 외부 API가 죽으면 시연도 죽음 | [확정] |

### 보안 규칙 (반드시 유지)

- 비밀번호는 **BCrypt로만** 저장. 평문·SHA 저장 금지
- Refresh Token **원문 저장 금지** — SHA-256 해시만. 재사용 감지 시 전체 무효화
- 로그인 실패 시 **아이디 오류/비밀번호 오류를 구분해 응답하지 않음** (둘 다 `AUTH_003`) — 계정 존재 여부 노출 방지
- Google idToken은 **`aud`(클라이언트 ID)와 `iss` 반드시 검증** — 빼면 다른 앱 토큰으로 로그인 가능
- 개인 SNS 링크는 **허용 도메인 화이트리스트 + https 강제** — 없으면 프로필이 피싱 링크 유포 통로가 됨
- 계정 삭제 시 개인 식별 정보(이메일·구글 sub·닉네임·프로필 이미지)는 **즉시 파기**. 30일 유예는 계정 레코드·콘텐츠에만 적용
- DB 비밀번호 · JWT secret · TourAPI 키 · AWS 키 · Firebase 파일 **절대 커밋 금지**

**캐물을 지점**
- 결정 6번(폴링): 심사위원이 "실시간이라면서 폴링이냐"고 물으면? → 대답 준비 필요
- 결정 10번: 서버가 Tier를 판정하려면 **촬영 시각·좌표를 어디서 얻나?** EXIF는 조작 가능하다. 이 부분 설계가 아직 얇음 [미검증]
- 결정 2번과 결정 4번 충돌: 지도는 비로그인도 보이는데, 히트맵 데이터는 로그인 사용자 업로드로만 채워진다 → 초기에 지도가 비어 보인다 (24시간 fallback으로 완화했지만 근본 해결 아님)
