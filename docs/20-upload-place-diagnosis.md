# 장소 선택 안내 및 게시 준비·전송 실패 진단

진단일: 2026-09-17. 관련 결정: DEC-20260917-006.

사용자는 지도 사진 수정은 장소 적재 후로 미루고, 장소 수동 선택 후 주변 장소 없음 안내와 등록 중 지속을 먼저 진단하도록 요청했다. 진단 도중 장소 적재 후 선택은 되지만 업로드 준비 실패가 발생한다고 추가 제보했다. 이 문서는 수정 전 코드와 연결된 실기기에서 확인한 사실을 구분한다.

## 장소 적재 후 현재 준비 실패: 외부 ID를 잘못 변환

연결된 실기기의 현재 작성 상태에서 다음을 확인했다. 사진·제목·인증 토큰·서명 URL·개인 위치는 기록하지 않았다.

```json
{
  "isSubmitting": false,
  "isMatchingLocation": false,
  "locationMessage": null,
  "matchCount": 12,
  "photoCount": 1,
  "selectedPlace": {"id": "plc_2zq", "name": "은구비공원"},
  "submitMessage": "업로드를 준비하지 못했어요. 사진과 장소를 확인한 뒤 다시 시도해 주세요."
}
```

서버 `api/auth/ExternalIds.java`는 장소와 행사 외부 ID를 `접두어_36진수`로 만든다. `plc_2zq`는 내부 장소 번호 3878이다. 게시 요청의 `CreatePostRequest.placeId`는 숫자를 받으므로 앱은 이 외부 ID를 정확히 숫자로 변환해야 한다.

그러나 `DeviceUploadRepository._numericId()`는 접두어를 제거한 뒤 기본 10진수 `int.parse()`를 호출한다. `2zq`는 숫자 변환 예외가 발생한다. `createPost()`는 업로드 URL 준비 후 `_createPostBody()`에서 이 함수를 호출하며 당시 단계는 preparation이다. 따라서 예외가 일반 preparationFailed로 변환되고 현재 안내가 표시된다. 사진 PUT과 게시글 저장 POST에는 도달하지 못한다.

숫자만 있는 외부 ID도 문제가 있다. `plc_10`은 내부 번호 36인데 현재 앱은 10을 보낸다. 최초 장소 `plc_1`은 두 진수에서 값이 같아 문제가 드러나지 않았고, 적재 후 더 큰 번호의 장소에서 드러난다. 같은 함수가 행사 ID·태그 추천·등급 미리보기에서도 사용되므로 변환 교정 시 모두 확인해야 한다.

필요한 수정: 접두어를 검증하고 외부 ID의 뒷부분을 `radix: 36`으로 해석한다. 준비 실패 안내는 내부 입력 변환 오류와 사진·서버 준비 오류를 구분해야 한다. 새로운 장소 적재나 키 재발급으로 이 코드 오류가 해소되지는 않는다.

## 수동 선택 후 주변 장소 없음 안내

`UploadController.selectPlace()`는 selectedPlace만 바꾸고 placeMatches와 locationMessage를 유지한다. 작성 화면은 selectedPlace가 아닌 placeMatches가 비었는지로 주변 장소 없음 안내를 결정한다. 자동 검색이 빈 결과였던 경우 수동 검색에서 장소를 선택해도 해당 장소 이름이 표시되지 않고 이전 안내가 남는다. 이 상태에서도 내부 selectedPlace가 있으면 게시 요청은 시작할 수 있다.

추가로 `_matchPlace()`는 늦게 완료된 자동 검색 결과를 그대로 반영한다. 자동 검색 중 직접 장소를 선택한 뒤 빈 응답이 도착하면 selectedPlace를 다시 null로 지운다. 수동 선택을 우선하거나 이전 자동 검색 응답을 무효화하는 보호가 없다. 실기기의 앞선 전송 실패 상태에서도 selectedPlace가 null이었지만, 선택이 지워진 정확한 시간 순서를 기기에서 수집하지 못했으므로 실제 시도의 경합 여부는 확정하지 않는다.

필요한 수정: 선택 장소를 작성 화면에 표시하고 이전 경고를 지우며, 수동 선택 이후 완료된 자동 검색이 선택을 덮어쓰지 않도록 처리한다. 검색 결과 목록에만 의존해 선택 여부를 표시해서는 안 된다.

## 앞선 등록 중 지속: 실제 상태는 사진 전송 시간 초과

앞선 실기기 프로세스의 UploadController가 참조하는 현재 상태를 추적해 다음을 확인했다.

- 선택 사진 2개, placeMatches 비어 있음, selectedPlace null.
- locationMessage: `주변 장소를 찾지 못했어요.`
- isSubmitting: false.
- submitMessage: `사진 전송 시간이 초과됐어요. 인터넷 연결을 확인한 뒤 다시 시도해 주세요.`

이 안내는 `_UploadStage.transfer`에서 TimeoutException이 발생할 때만 생성된다. 원본 사진 읽기와 업로드 대상 준비를 지나 저장소 사진 PUT에서 제한 시간을 초과한 것이다. 저장 요청은 사진 전송 성공 후에만 실행되므로 이 실패 시도는 게시글 저장 단계에 도달하지 않는다. 처음에는 대기 제한이 없는 원본 읽기를 의심했으나, 실제 상태는 전송 시간 초과이므로 해당 가설을 이번 시도의 원인으로 채택하지 않는다.

사진 PUT의 제한은 한 장당 60초다. 화면은 구체적 단계·진행률 없이 등록 중만 표시하므로 오래 기다리는 동안 원인을 알기 어렵다. 오류 안내는 작성 내용 아래에 표시되어 사용자가 즉시 보지 못할 수도 있다. 무응답 PUT을 로컬에서 재현했을 때 59초에는 대기 중이며 60초에 photoUploadTimeout으로 종료됐다. 영구적으로 isSubmitting이 true인 현상은 이번 기기 상태에서 확인되지 않았다.

사진 전송이 지연된 하위 원인(기기 통신·DNS/TLS·저장소 연결·전송 속도)은 아직 확정하지 못했다. 이미 실패한 요청의 HTTP 기록이 없고 진단 중 기기 앱 프로세스가 새로 시작되어 당시 서명 주소·요청 상태를 더 추적할 수 없었다. 향후 해당 문제를 재현할 때는 사진 바이트 수, 단계별 소요 시간, 저장소 응답 상태를 민감 정보 없이 수집해야 한다. 클라이언트 전체 제한이 없는 원본 읽기는 별도 잠재 위험이며 이번 전송 실패와 구분한다.

## 검증 및 변경 범위

실제 서버에 게시글·사진을 추가하지 않고 기존 테스트 도구로 임시 진단 테스트 5개를 실행했다. 모두 수정 전 동작을 재현했다.

1. 자동 검색 빈 결과 → 직접 검색·선택: 내부 장소가 저장되고 가짜 등록은 성공하지만 화면의 이전 경고는 남는다.
2. 진행 중 자동 검색 → 수동 선택 → 늦은 빈 응답: 선택한 장소가 null로 지워진다.
3. 사진 PUT 무응답: 60초 후 전송 오류, 게시글 저장 POST 없음.
4. 실기기와 같은 `plc_2zq`: 업로드 URL 준비 후 준비 실패, 사진 PUT·게시글 POST 없음.
5. `plc_10`: 장소 36 대신 10이 게시 본문으로 전송되는 잘못된 변환 확인.

임시 테스트·디버거 도구는 Git 제외 build에만 생성했다. 연결한 디버거는 해제하고 로컬 기기 포트 전달을 제거했다. 앱·서버 구현, 키, 운영 데이터는 이번 진단에서 수정하지 않았다. 사용자가 수행한 장소 적재는 별도 작업이다.

## 후속 앱 수정 완료 (2026-09-17, DEC-20260917-007)

사용자의 후속 수정 요청으로 다음을 구현했다. 앞선 진단 시점의 사실과 구분한다.

- `_numericId()`는 접두어·허용 문자·양수 여부를 검증하고 36진수로 변환한다. 게시글 저장, 태그 추천, 등급 미리보기에 같은 변환을 적용한다.
- 게시할 장소·행사 번호를 사진 읽기와 업로드 URL 요청 전에 검증한다. 잘못된 번호는 장소·행사별 안내를 반환하고 사진 준비 요청을 보내지 않는다.
- 작성 화면은 실제 선택된 장소를 먼저 표시한다. 자동 검색 후보에 없는 장소를 선택해도 표시하며, GPS 매칭 여부와 수동 선택 완료를 구분한다.
- 수동 선택 시 기존 위치 안내와 진행 표시를 해제한다. 자동 검색의 세대를 추적해 수동 선택 또는 행사 적용 이후 완료된 이전 자동 검색의 결과·오류가 선택을 덮어쓰지 못하게 한다.

검증: 저장소·작성 화면 회귀 테스트 27개 통과, 수정한 코드와 테스트 5개 파일 정적 검사 문제 없음, APK debug 빌드 성공. `plc_2zq` → 3878 및 `plc_10` → 36, 문자 포함 행사 ID와 숫자 전용 행사 ID, 태그·미리보기, 잘못된 접두어·0·음수·공백 입력, 검색 선택 이후 완료·실패한 자동 매칭을 검증했다.

연결된 SM-S921N에 기존 앱 위로 업데이트 설치했다. 설치 도구의 Success, 설치 시간 2026-09-17 02:06:42, 앱 프로세스 실행 및 실행 직후 오류 로그 0건을 확인했다. 서버 코드·운영 DB·키는 이 후속 수정에서 변경하지 않았으며, 실제 사진·게시글 저장은 검증용으로 실행하지 않았다. 실기기의 실제 전송 시간 초과와 운영 저장 결과는 사용자 재시도 시 별도로 확인해야 한다.
