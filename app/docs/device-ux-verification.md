# Android 실기기 UX·연결 점검

검증일: 2026-09-07. 적용 결정: DEC-20260907-015, DEC-20260907-016, DEC-20260907-017, DEC-20260907-018, DEC-20260907-019.
연결된 Samsung SM-S938N에서 기존 설치를 데이터 초기화 없이 업데이트했다.
로컬 백엔드는 ADB reverse 8080으로 연결했고, 앱은
`flutter run -d <physical-device> --dart-define=API_BASE_URL=http://127.0.0.1:8080`
설정으로 실행했다. 에뮬레이터와 구분하여 실기기만 조작했다.

## 수정 및 실기기 재검증

| 동선 | 발견한 문제 | 수정·확인 결과 |
|---|---|---|
| 비회원 → 마이 → 로그인하러 가기 | 로그인 페이지가 다시 홈으로 리다이렉트됨 | 비회원의 로그인 페이지 진입 허용. 실제 Google 로그인 버튼이 있는 화면까지 이동 확인 |
| 로그인 안내 표시 | 탐색 화면 대신 전북 샘플 게시글 배경 표시 | 현재 탐색 화면 위에 반투명 안내 표시. 홈 지도 배경을 스크린샷으로 확인 |
| 안내 취소·로그인 화면 뒤로가기 | 실제 탐색 문맥과 연결되지 않음 | 기존 화면 스택 보존. 지도 복귀, 공개 프로필 팔로우 안내 취소 후 동일 프로필 유지 확인 |
| 지역 패널 → Android 뒤로가기 | 앱이 종료되어 이전 Android 화면으로 이탈 | 패널만 닫히고 홈 지도 유지 |
| 지역 패널 축소 → 같은 지역 선택 | 상태의 높이만 초기화되고 실제 패널은 축소 상태 유지 | 스크롤 컨트롤러로 높이 복원. 서울 패널 상단이 기기 좌표 y=2201에서 원래 y=1343으로 복원됨 |
| 위치를 선택하지 않은 홈 | 실제 위치를 얻지 않았는데 ‘현재 위치’로 표시 | ‘지역 선택’으로 표시 |
| 로그인 안내의 취소 버튼 | 밝은 브랜드 글자색으로 가독성 부족 | 어두운 본문 글자색 적용 |
| Google 로그인 SDK 초기화 | 기존 `.env`에 OAuth ID가 있지만 별도 dart-define만 읽어 `serverClientId` 누락 | 기존 실행 옵션 우선순위를 보존하며 로드된 `.env`의 OAuth ID 연결. 앱·백엔드 설정값의 일치 여부만 확인했으며 값은 기록하지 않음 |
| Google 계정 선택 후 복귀 | SDK의 `canceled` 결과를 아무 안내 없이 종료 | 비회원 세션을 보존하며 로그인 미완료 안내 표시. 후속 서버 연결·설정 복구 뒤 실제 프로필 설정 진입 확인 |
| 프로필 설정 → 소개글 | 전역 검색창의 고정 높이 38이 적용되어 4줄 입력 영역이 높이 0으로 눌리고 입력 내용이 안 보임 | 해당 화면의 입력 장식에서 고정 높이만 해제. 4줄 입력 영역·160자 카운터 표시 및 기존 입력 보존을 hot reload 후 실기기 확인. 키보드가 열린 상태에서 입력 내용·커서 표시 확인. 큰 글자·키보드가 있는 좁은 화면의 스크롤 접근은 위젯 테스트로 추가 확인 |

추가로 홈 서울 게시글 3개 조회, 작성자 공개 프로필 조회,
팔로워 1명 목록 → 해당 사용자 공개 프로필 이동을 실기기에서 확인했다.
비회원 팔로우 테스트는 인증 안내까지만 진행했으며 변경 API를 보내지 않았다.

## 자동 회귀 검증

- `dart format .`: 기존 Android 빌드 캐시의 Windows 생성 경로 순회 중
  `PathNotFoundException` 발생. 경로는
  `build/flutter_plugin_android_lifecycle/.transforms/.../bundleLibRuntimeToDirDebug_dex/...`.
  빌드 캐시를 삭제하지 않고 실제 Dart 소스에 대해 재검증했다.
- `dart format lib test`: 98개 파일 통과.
- `flutter analyze`: 문제 없음.
- `flutter test`: 단위·위젯 통합 73개 통과. 별도 구분 없이 전체 실행.
- `git diff --check`: 통과.
- 실기기 hot restart로 라우터 갱신 후 재검증, 최종 수정 hot reload 성공.
  Dart 런타임 오류 조회 결과 없음.
- 초기 UX 수정본의 Android debug APK 재빌드(20.6초)·업데이트 설치(4.9초) 성공.
  이후 OAuth 설정·미완료 안내를 포함한 최종 APK도 재빌드(18.6초)·업데이트 설치(4.6초) 성공.

새 회귀 테스트는 비회원 로그인 진입·취소·로그인 후 원래 목적지 복귀,
보호 경로 인증 유지, 앱 외부 복귀 주소 차단, 공개 프로필 복귀,
Google 로그인 취소/실패 시 비회원 세션 유지, 740×320 로그인 레이아웃,
지역 패널 뒤로가기와 동일 지역 재선택을 포함한다.
OAuth 설정 이름·우선순위·빈 값·dotenv 로딩, 로그인 미완료 피드백도 추가 검증했다.
프로필 설정 소개글은 실제 AppTheme 아래에서 4줄 높이·줄바꿈·카운터 분리,
360×640 화면의 큰 글자(1.5배)·키보드 300 높이에서 스크롤 접근,
기존 160자 입력 제한을 검증한다. 레이아웃 테스트는 수정 전 실제 입력 영역 높이 0으로
실패했고, 수정 후 통과했다. 실계정의 닉네임·소개글·약관 선택·제출은 변경하지 않았다.

## Google 계정 선택 이후 로그인 차단 (초기 현상)

사용자가 계정 선택창에서 계정을 선택한 뒤 화면 변화가 없다고 확인했다.
실기기 로그는 `GetCredentialResponse error returned from framework`,
앱에서 개인정보 없이 출력한 SDK 결과 코드는 `canceled`였다.
Google SDK는 일부 설정 오류도 취소로 반환하므로 사용자 취소로 단정할 수 없다.
패키지명·서명 SHA-1·Web OAuth 클라이언트의 같은 프로젝트 등록 여부 대조가 필요하다.
현재 연결된 Google Cloud 콘솔이 없어 등록값의 일치 여부는 확인하지 못했다.

현재 debug 앱의 공개 등록 정보 (`:app:signingReport` 확인):

- 패키지명: `com.snaphere.snap_here`
- SHA-1: `9D:69:B9:F1:C3:B0:39:3E:29:9A:6E:A5:D6:38:C0:B4:C3:DC:26:45`
- `serverClientId`에는 Android 클라이언트 ID가 아닌 같은 프로젝트의 Web 클라이언트 ID를 사용한다.

출처: [Flutter Google Sign-In Android 문제 해결](https://pub.dev/packages/google_sign_in_android),
[Google의 Android 앱 서명 인증 안내](https://developers.google.com/android/guides/client-auth).
클라우드 OAuth 등록 변경, 서명 키 교체, 인증 우회는 수행하지 않았다.

### Google 인증 결과 수신 이후 로컬 서버 연결 복구

사용자의 콘솔 설정 수정 이후 14:42 실기기 로그에서
`GetCredentialResponse returned from framework`를 확인했다.
이때 앱은 일반적인 로그인 오류를 표시했다. 재점검 당시 ADB reverse 목록에
8080 전달이 없어 `adb -s <physical-device> reverse tcp:8080 tcp:8080`을 복구했다.
PC의 `/api/v1/map/regions`는 HTTP 200을 반환했다.

기존 테스트 백엔드는 에이전트가 12:18에 시작한 PID 22656이었고, 저장소 루트의
OAuth 설정 파일은 13:57에 수정되어 실행 중 서버에 새 설정이 반영되지 않은 상태였다.
동일 앱 프로세스인지 확인한 뒤 해당 PID만 종료하고 같은 JDK 21.0.11·기존 Gradle
설정으로 재시작했다. 새 PID 50188의 8080 정상 응답을 확인했다.
사용자가 수정한 `backend/.vscode/launch.json`, DB·스키마·인증 검증 로직은 변경하지 않았다.

앱의 로그인 교환은 API 오류 코드와 네트워크 예외를 기존 AuthFailure로 변환한다.
서버 연결 실패, 응답 지연, 앱·서버 OAuth 대상 불일치, 잘못된 Google 토큰,
일반 서버 오류를 구분하며 비회원 세션을 보존한다. 토큰·서버 응답 원문은
로그에 출력하지 않는다. 이 변경의 계약·오류 안내 테스트 9개를 추가했다.
오류 안내 수정본은 debug APK 빌드(15.5초)·실기기 업데이트 설치(4.5초)를 완료했고,
hot reload 성공 및 런타임 오류 없음도 확인했다.

후속 실기기 확인에서 `프로필 설정` 화면 진입을 확인했다. 해당 경로는 인증된
세션의 `needsProfileSetup` 상태에서만 접근할 수 있으므로 Google 인증과 백엔드
토큰 교환까지 성공한 것으로 검증했다. 닉네임 입력·약관 동의·완료 제출은
사용자가 직접 진행하도록 남겼다. 따라서 가입 완료 후 마이·뱃지 조회까지
검증한 것은 아니다.

## 남은 미구현·검증 제한

- `/photos/:id`, `/places/:id`, `/notifications`는 기존 안내용 placeholder 화면이다.
  신규 상세 화면 구현까지 확대할지 사용자에게 확인을 요청했으며 이번 수정에는 추가하지 않았다.
- 커뮤니티 팔로잉 피드는 `ApiCommunityRepository.fetchFeed`에서 빈 목록을 고정 반환한다.
  현재 백엔드 `FeedController`에는 `/feeds/recent`만 있고 `/feeds/following`은 없다.
  실제로 팔로우한 사용자가 없는 것으로 해석하면 안 된다. 프런트·백엔드 추가 구현이 필요하다.
- 커뮤니티 검색은 `/search` 계약에 연결되어 있지 않고 `/posts` 첫 50건을
  클라이언트에서 필터링한다. 전체 검색은 입력어를 태그 조건으로 먼저 제한하므로
  작성자·장소명 검색이 누락될 수 있다. 코드 점검 사항이며 이번에 검색 구현은 변경하지 않았다.
- 로컬 초기 데이터의 사진 주소가 `example.invalid`여서 대체 이미지가 표시된다.
  게시글 상세의 ID/공개 준비 상태 제약은 기존 `home-profile-verification.md`를 참고한다.
  데이터나 서버 공개 조건을 임의로 바꾸지 않았다.
- 실제 Google 계정 인증·백엔드 토큰 교환·프로필 설정 진입까지 확인했다.
  가입 완료 후 로그인된 마이·뱃지, 팔로우 변경 및 게시물 업로드는 실기기에서
  확인하지 않았다. 해당 개인 데이터·변경 동작은 테스트 대역으로 검증했다.
- iOS 실기기 검증은 하지 않았다. 신규 패키지·네이티브 권한·API·DB 변경은 없다.

실기기는 위 로컬 서버 연결이 살아 있을 때 API를 사용할 수 있다.
기존 사용자 파일은 보존했으며 이 UX 수정의 커밋·push는 아직 하지 않았다.
