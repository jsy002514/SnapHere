# 홈·마이 Figma 구현 확인

대상: `rAmlL9refXsmqJwj2h3L43`의 홈 `92:311`, 마이 `92:1931`.
적용 결정: DEC-20260907-012, DEC-20260907-014 (013의 SDK 승인 대기 해제).

## 화면과 연결

| 화면 | 구현·연결 |
|---|---|
| 홈 기본·지역 선택·축소/확장 시트 | Google Maps, `/map/regions`, `/posts?areaCode=…&period=WEEKLY`, 위치 버튼·권한 거절 안내 |
| 내 프로필·게시글·빈 상태 | `/me`, `/users/{userId}/posts`, 설정·업로드 진입 |
| 타 사용자 프로필 | `/users/{userId}`, 사용자 게시글 2열 카드 |
| 팔로워·팔로잉 | `/users/{userId}/followers`, `/following`, 공개 프로필 통계 보충 |
| 팔로우 토글 | `PUT/DELETE /users/{userId}/follow`, 중복 요청 차단·서버 상태 반영·프로필 통계 재조회 |
| 방문 지도·수집한 뱃지 | `/me/visit-map`, `/users/me/badges`, `/badges/{badgeId}` |

경로에는 기존 ApiClient의 `/api/v1` 접두어가 적용된다. 목록은 서버 커서를
해석하지 않고 12개씩 조회한다. 카드 본문·팔로우 목록 통계 보충 조회는
동시 4개로 제한하며 실패한 보충 데이터 대신 이미 받은 요약을 보존한다.
팔로우는 비회원에게 로그인 안내를 표시하고 실제 변경 요청을 보내지 않는다.

화면 배치는 요청한 Figma를 따른다. 내 게시글은 큰 카드 목록, 타 사용자
게시글은 2열 카드, 뱃지는 획득한 항목 목록이다. 기존 문서의 3열 격자·미획득
뱃지 표시까지 완료한 것으로 간주하지 않는다. 지역 선택은 Figma의 지도 위
시트를 사용한다. 히트맵·사진 마커 레이어, 시도 경계 채색은 이번 화면에
추가하지 않았으며 API·DB 계약과 원본 명세 스프레드시트는 변경하지 않았다.
사진·장소·알림 버튼은 기존 상세 라우트로 연결하며 해당 라우트의 미구현
상세 페이지는 이번 작업에서 확장하지 않았다.

## 실행 설정

- 승인한 `google_maps_flutter: 2.18.0`을 정확히 고정했다.
- Android는 앱 `.env`의 `GOOGLE_MAPS_API_KEY` 또는 동일 이름의 CI 환경변수를
  Manifest에 주입한다. iOS는 기존 dotenv 로딩 후 플랫폼 채널로 SDK를 초기화한다.
- 키 값은 커밋하지 않는다. 기존 위치 권한 외 새 권한을 추가하지 않았다.
- Android 에뮬레이터 실행: `flutter run -d emulator-5554 --dart-define=API_BASE_URL=http://10.0.2.2:8080`
- 키가 없거나 지원하지 않는 플랫폼은 지도 설정 안내를 표시한다.

## 검증 결과 (2026-09-07)

- Dart 소스 포맷: `dart format lib test` 통과.
- `dart format .`은 기존 `build/flutter_plugin_android_lifecycle/.transforms`의
  Windows 생성 경로를 순회하다 PathNotFoundException 발생. 빌드 산출물을 삭제하지
  않고 실제 프로젝트 Dart 소스 전체를 별도로 포맷했다.
- `flutter analyze --no-pub`: 문제 없음.
- `flutter test --no-pub`: 단위·위젯 통합 46개 통과.
- Android 디버그 APK 빌드·설치, 실제 Google 지도 및 지역 게시글·공개 프로필 조회 확인.
- 90px 홈 사진, 64px 프로필, 160px 내 게시글 사진, 100px 타 사용자 사진,
  42px 팔로우 버튼, 280px 방문 지도, 40px 뱃지 아이콘을 위젯 테스트로 확인.
- 페이지 재시도 시 기존 목록 유지, 팔로우 중복/실패/비회원 차단, 뱃지 상세와
  획득 게시글 라우팅, 초기 화면 높이가 0에 가까울 때의 레이아웃 회귀 테스트 포함.
- iOS 빌드·실기기, 로그인된 실제 계정의 팔로우 변경·개인 방문 데이터는 미검증.
  개인 데이터와 변경 요청은 테스트 대역으로 검증했다.

### 로컬 서버 데이터 제약

공개 조회 API는 200을 반환한다. 초기 데이터의 사진 주소는 `example.invalid`라
이미지 대체 상태가 표시된다. 게시글 목록의 ID `1001`에 대한 상세 조회는
`POST_NOT_FOUND`, 서버의 외부 ID 형식 `pst_rt`로 직접 확인하면
`POST_NOT_VISIBLE`을 반환했다. 앱에서 임의로 ID를 변환하거나 서버 데이터를
수정하지 않았으며, 본문 보충 실패 시 장소명을 카드 제목으로 표시한다.
실제 사진·공개 상세 데이터의 준비 여부는 백엔드 측 확인이 필요하다.
